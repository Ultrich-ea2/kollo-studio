# Export decisions and verification

The versioned deck and deterministic 1280×720 scene are the only export inputs. Export functions return Blobs; the application chooses filenames and whether to include notes. Overflow warnings stop the export instead of silently clipping text. Raster exports render the shared SVG scene to 2560×1440 PNG sequentially. They need a browser canvas and the platform Arial/Georgia fonts (plus Courier New for code). PDF uses an exact 960×540pt landscape page per slide, containing the entire PNG. Raster PDF text is not searchable; raster PPTX is not a native editable slide.

Editable PowerPoint uses native single-line text, shapes and images. It uses 96px/in, 0.75pt per scene font pixel, zero text margins and disabled text wrapping. PowerPoint and browser typography can still differ, and fonts are not embedded. WebP images are converted locally to PNG for PowerPoint compatibility. Image decoding is capped at 40MP and 16384 pixels per dimension.

HTML includes the deck artwork and optional speaker notes, a fixed player, navigation/reveal groups, timer, simple transitions, reduced-motion styling and a print layout that reveals all content and hides all notes. It loads no remote assets. A SHA-256 CSP permits only the fixed player script. Notes are hidden by default and shown only by explicit action; notes included in a file can always be read in its source. The application must remove notes before export when the user has not opted in.

The kit is built entirely from resources imported at build time via Vite raw globs. It includes `presentation.html`, `deck.kollo.json`, `EXPORTS.md`, `guide.md` and `skills/kollo-theme/**`. It performs no network fetch. Project JSON remains the editable backup, including notes passed to the exporter. The skill is documentation and an optional checker; no downloaded project code is evaluated.

## Transition mapping

Upstream PptxGenJS4.0.1 exposes no public transition/animation API. A closed OOXML postprocessor handles only packages freshly generated by that version. It validates ZIP entry paths, the expected package parts, sequential slide paths and the exact upstream slide suffix. It rejects pre-existing transition/timing structures. `none` adds nothing, `fade` adds `p:fade`, `slide` adds `p:push dir="l"`, and browser `zoom` falls back to fade. Only click advancement and medium base-schema transition speed are used; no automatic advancement, modern duration extension, Morph, or object-animation trees are promised. Reveal groups are all visible in PPTX/PDF.

## Verification plan

- Unit tests inspect ZIP entries, native text/shapes/notes, XML transition mapping and absence of full-slide raster content in editable text decks. Test HTML escaping, CSP script hashes, notes hidden state, print/reduced-motion rules, kit round trips and unsafe ZIP paths.
- Browser tests export all modes from every layout, check landscape PDF geometry/page counts and render all pages. Compare raster PDF with the SVG stage; inspect accents, long lines, symbols, images, charts and page edges.
- Open editable and visual PPTX in PowerPoint without a repair prompt. Change native text, inspect notes and run every transition. Compare every rendered slide against the stage on the actual target fonts/platform; LibreOffice is an additional compatibility check, not a PowerPoint substitute.
- Disconnect networking and open the downloaded HTML from a clean browser profile. Check no requests, keyboard/reveal navigation, timer, explicit notes toggle, reduced-motion setting and print output of every slide without notes.
- Exercise invalid imports, overflow, oversized/unsupported images, Canvas errors, archive failures and unusual Unicode. Export errors must be displayed without a partial download or silent truncation.
