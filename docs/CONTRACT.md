# Kollo implementation contract

Student presentation studio with a reusable theme and flexible slide structure. German interface; three editable academic example decks explicitly marked as fictitious. The author has separately authorized publication of his original 6:32 DELFI demonstration, including its original credits and timed narration text. Other personal research and feedback are not published. The AI skill remains general and contains no DELFI-specific instructions or source materials. Repository source, offline kit and a general AI authoring/adaptation skill are in scope; Vercel hosting. The studio processes presentation content on device; users control any separate sharing with an AI service.

Shared model (src/model.ts): Deck {version:1,title:string,author:string,institution:string,date:string,duration:number,theme:{background:string,foreground:string,muted:string,primary:string,secondary:string,font:'Arial'|'Georgia',scale:number,showProgress:boolean},slides:Slide[]}. Slide {id:string,layout:'title'|'section'|'bullets'|'columns'|'process'|'stats'|'quote'|'code'|'image'|'chart'|'references'|'closing',section:string,title:string,subtitle:string,items:string[],body:string,image:string,imageAlt:string,notes:string,source:string,transition:'none'|'fade'|'slide'|'zoom',reveal:boolean,seconds:number}. All fields required. Images only embedded PNG/JPEG/WebP, no remote URLs or SVG. Items format: columns uses two strings; stats/chart use "value | label"; chart numeric nonnegative values.

Exports and UI share a deterministic scene at 1280x720. src/scene.ts exports createScene(slide,deck,index): Scene {background:string,elements:Element[],warnings:string[]}. Elements: Rect {type:'rect',x,y,w,h,fill,stroke?:string,radius?:number,group?:number}, Text {type:'text',x,y,w,h,text,fontSize,color,bold?:boolean,font?:string,align?:'left'|'center'|'right',group?:number}, Image {type:'image',x,y,w,h,src,alt,group?:number}. Text elements contain a single already-wrapped line. Font size pixels. Scene text top coordinates; shared export mapping must account for font baselines. createScene never drops content silently: warn on overflow. svgMarkup(scene): string escapes all text. Visible animations grouped by group integer.

src/model.ts exports defaultDeck (10-12 example slides), layouts Record<layout,string>, createSlide(layout), parseDeck(input:unknown): Deck throws clear German errors, validateDeck(deck): string[], templates Array<{id,name,description,deck}>, cloneDeck(deck):Deck. Import max file 10MB, <=80slides, bounded fields/items/data images, reject invalid schema/prototype keys, preserve valid input exactly (no silent truncation).

src/exports.ts exports async exportPptx(deck,mode:'editable'|'visual'):Promise<Blob>, exportPdf(deck):Promise<Blob>, exportHtml(deck):Promise<Blob>, exportKit(deck):Promise<Blob>, downloadBlob(blob,filename). No automatic download inside exports. Pure standalone HTML plays embedded slides with keyboard navigation/reveals, timer and notes; no network. Editable PPTX uses native scene shapes/text and speaker notes. Visual PPTX and PDF use high-resolution rendered scenes. Disclosure of animation fidelity per format. PPTX basic transition supported via safe OOXML patch if tested, browser-only effects clearly disclosed.

The optional theme.composition field accepts classic, editorial, technical or stage. Absence preserves the existing classic rendering and original JSON. The portable Python validator and browser validator share the same allowed values. New designs do not change the twelve layout names.

src/presenter/runtime.mjs is the common dependency-free player for the React studio, standalone HTML and the DELFI video adapter. All examples share navigation, notes, a separate teleprompter and a separate audience window. The controller owns slide/phase/time/blackout state and directly held child windows. Audience DOM excludes notes. Reading speed is an estimate, not speech recognition. A separate-window reload reconnects with a fresh window identity; a child navigated away is no longer owned. Popup opening requires a direct user action. No cross-device synchronization is offered.

Optional private notes cues use exact standalone lines [KLICK] and [FOLIE], with surrounding horizontal whitespace allowed. KLICK corresponds to the next actual reveal group or curated media phase; FOLIE advances to the next slide after its last phase. They render inside the speech text as private action cues, excluded from spoken-word timing. A running reader pauses at an outstanding cue; no cue, reader timer or presentation timer automatically advances the audience presentation. Right advances one phase, and Left restores the preceding phase, including the final state of the previous slide when invoked at a slide's baseline. Every manual phase change aligns the reader to that phase's speech and pauses reading. Early advancement deliberately selects the next phase and its explanation rather than preserving the old reading position. Starting or resetting the reader does not reset visible phase state. The persistent next-action hint is also available with ordinary notes, including focus and mobile views. Validate authored cues against actual rendered reveal groups or reviewed media phases; advisory Python checks cannot replace that visual and runtime check. Existing arbitrary bracketed directions remain ordinary notes. PowerPoint retains markers as note text, without these HTML runtime behaviors. Markers do not create missing animations, and arbitrary elapsed-time intervals are not a substitute for a meaningful phase plan.

Student distribution separates examples, skills, studio, source and guides, with a local START-HIER.html entry point. scripts/sync-skill-examples.ts generates portable skill examples from the authored src/examples.ts; scripts/build-examples.ts generates actual HTML/JSON/SVG/PPTX examples. scripts/package.mjs packages only curated project trees. Private QA material stays outside public source and archives. The offline editor is served only on loopback and does not include a recursive copy of its own distribution archive.

The authorized DELFI showcase uses the shared player through a media adapter while remaining separate from the importable Kollo deck model. Its maintained source is under showcases/delfi: content, phases.json, scene baseline frames, HTML template, CSS, JavaScript, original MP4, preview JPEG and provenance. Preserve the original media bytes, sixteen scene timings, speech text and credits to Ultrich Edima Edima and André Greubel. The video is 392 seconds long, 1920×1080, and has no audio track. Actual presentation duration is determined by manual clicks and speaking pauses. It is a historical software demonstration dated 2026-09-08, not a new performance claim or an editable slide template. The generic Kollo JSON schema does not gain media fields from this adapter.

DELFI's reviewed phase plan contains 81 semantic media phases across all sixteen scenes. Each scene has a baseline time and parallel arrays of absolute starts, stops, labels and original-speech character offsets. Video and speech hashes bind the plan to its source. Require ordered finite times within the scene, one label and offset per phase, ascending word-boundary offsets and exact reconstruction of the original speech after removing inserted markers. The original files did not author these phase cues; document their visually inferred provenance. Parallel or tightly connected animation may form one phase; decorative loops do not require new cues. Playback starts skip suitable static holds while retaining the actual animation, including thin connecting lines. Scene-specific baseline JPEGs provide upcoming previews and fallback imagery.

Right plays only the next media phase and pauses at its stop. Right during playback completes the current phase first; a subsequent press is required for another phase. Left cancels playback and seeks the previous phase state. A final phase never starts the next scene automatically. The teleprompter follows the manually selected phase rather than elapsed video time. User speech is not recorded or recognized. The main controller owns its child windows; multiple independent controllers must not take over one another's windows. Preserve offline playback and do not make network requests to the linked software demo automatically. Hosted execution must work under the deployed CSP without relaxing script policy for the whole site.
